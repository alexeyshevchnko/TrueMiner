# Terrain Stone Framing — 2026-11-25

Работа по автотайлингу (tile framing) **земли** и **камня** на оригинальных тайлсетах Terraria
(`Tiles_0`, `Tiles_1`) в Unity-проекте **TrueMiner**, с поведением, повторяющим
`WorldGen.TileFrame` из **Terraria 1.4.4.9**.

---

## Цель работы

Заменить упрощённую схему `TerrainTileShema` (выбор из ~20 фиксированных кадров по 4 соседям)
на полноценный Terraria-совместимый framing: кадр выбирается по 8 соседям (4 стороны + 4
диагонали) с учётом краёв, внешних/внутренних углов, полос, одиночных блоков и переходов
земля↔камень. Архитектура должна позволять добавлять новые блоки без переписывания движка.

## Что реализовано

1. **Классификация соседей** в три слота, как в оригинале: `SlotSelf` (`== num`),
   `SlotMerge` (маркер `-2`), `SlotEdge` (`-1`); пустота, вода, деревья, декор — `SlotEdge`.
2. **Правила соединения** (`TerrariaTilesetRules`) — данные, а не код: «свои» типы, типы-слияния,
   типы с взаимной проверкой, участие в merge-блоках.
3. **Решатель кадров** (`TerrariaFraming.Solve`) — построчный перенос веток `WorldGen.TileFrame`:
   - Блок 1: 15 комбинаций слияния при всех четырёх сторонах + диагональные слияния;
   - Блок 2: 22 ветки частичных слияний (колонка 234, «полки», два слияния, одиночные слияния);
   - Блок 3: generic-цепочка из 16 взаимоисключающих веток со **строгим** сравнением `== SlotSelf`;
   - Блок 4: финальный fallback `(18+18v, 18)`.
4. **Взаимная проверка земли с камнем** (`TerrainTileShema.ResolveMutualSlot`) — аналог
   `TileMergeAttemptFrametest`: земля считает камень «своим», только если камень сам
   сливается в её сторону. Для реализации нужен окно 5×5 (`SquareSizeByShema = 5`).
5. **Прежняя схема сохранена** для остальных тайлсетов: `LegacyTerrainTileShema.cs`.
6. **Локальное обновление кадров**: `RedrawWorldTile5X` (5×5) для террейн-слоя при
   установке/удалении блока.
7. **Тестовый стенд** вне Unity: таблица всех 57 веток, брутфорс всех комбинаций, фаззинг,
   детерминизм, производительность, визуальные атласы, рендер тестовой карты.

## Как запустить тесты

Требования: **.NET SDK 10**, Windows (используется `System.Drawing`).

```powershell
cd D:\projects\TrueMiner\Agent_Works\Terrain_Stone_Framing_2026-11-25\tests

# 1. Собрать и прогнать все проверки (код возврата 0 = всё прошло)
dotnet run -c Release

# 2. Отрисовать тестовую карту из посчитанных кадров
powershell -NoProfile -ExecutionPolicy Bypass -File .\render_preview.ps1

# 3. Крупный зум на полосу камня (y = 13..22)
powershell -NoProfile -ExecutionPolicy Bypass -File .\render_preview.ps1 -Zoom 8 -X0 0 -Y0 13 -X1 22 -Y1 22 -Out zoom_strip.png
```

Тесты компилируют **настоящие** файлы игры по абсолютным путям
(`D:\projects\TrueMiner\Assets\...`), поэтому проверяется именно рабочая реализация, а не копия.
`Stubs.cs` подменяет только `TileInfoStructure` и пустое пространство имён `UnityEngine`.

Выходные артефакты складываются в каталог `tests/`:
`terrain_frames.csv`, `terrain_preview.png`, `zoom_strip.png`,
`framing_sheet_stone.png`, `framing_sheet_dirt.png`, `diagnostic.csv`.

## Коротко: в чём была главная ошибка

Предшествующая реализация ввела в generic-цепочке (Блок 3) проверку
`IsConnected(slot) = (slot == SlotSelf || slot == SlotMerge)` и использовала её вместо строгого
`== num`. В оригинале маркер слияния `-2` в generic-цепочке **не** считается соединённым — он
ведёт себя как пустота. Из-за этого, например, для `up=Merge, down=Merge, left=Edge, right=Self`
(торец тонкой полосы камня) выбирался кадр «левый край» `(0, 18v)` вместо ветки 76873 → `(162, 18v)`.

Подробности: `WORK_REPORT.md`, §«Итоговая причина»; доказательство — `references/`.
