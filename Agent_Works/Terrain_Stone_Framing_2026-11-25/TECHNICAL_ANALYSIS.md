## 1. Классификация соседей: Self / Merge / Edge

Оригинал работает с числовыми значениями типов и двумя маркерами
(`WorldGen.cs:73654–73709`):

| Значение в оригинале | Смысл | Наш слот |
|---|---|---|
| `num` (тип самого тайла) | сосед того же типа | `SlotSelf = 1` |
| `-2` | «запрос слияния» (ставится `TileMergeAttempt`) | `SlotMerge = -2` |
| `-1` | пустота (или тип, приведённый к пустоте) | `SlotEdge = -1` |

Инициализация: неактивные тайлы остаются `-1`; активные получают `type`
(для «каменных» типов принудительно `1`; наклоны обнуляют сторону).

Затем:

1. `TileMergeAttempt(0, TileID.Sets.Dirt, ...)` (73734) — соседи-земля становятся `0`.
2. Для **камня** (`Main.tileMergeDirt[1] = true`) — `TileMergeAttempt(-2, TileID.Sets.Dirt, ...)`
   (74141): соседи-земля становятся **`-2`**.
3. `if (up > -1 && up != num) up = -1;` (75563–75578) — любой **чужой реальный** тип
   превращается в `-1` (у нас это уже делает `ClassifyNeighbor`, возвращая `SlotEdge`).

### Почему земля и камень ведут себя по-разному

`TileID.Sets.Dirt = {0, 668}`, `TileID.Sets.Stone = {1, 25, 117, 203}`,
`Main.tileMergeDirt[1] = true` (см. `references/TileID_and_Main_facts.md`).

| Тип | Ветка оригинала | Поведение |
|---|---|---|
| Земля (type 0) | `if (TileID.Sets.Dirt[num])` — **73936** | merge-блоков **нет**; камень проверяется **взаимно** |
| Камень (type 1) | `if (Main.tileMergeDirt[num])` — **74139** | соседи-земля → `-2`, работают merge-блоки |

### Взаимная проверка (только земля)

`WorldGen.cs:73938–74001`: для каждого кардинального соседа, который
`Main.tileMergeDirt` (т.е. камень), вызывается `TileFrame` соседа, и если у него
взведён соответствующий флаг (`mergeDown` для верхнего, `mergeUp` для нижнего,
`mergeRight` для левого, `mergeLeft` для правого) — сосед заменяется на `num` (Self).

Диагонали (`74019–74047`): `if (upLeft > -1 && Main.tileMergeDirt[upLeft]) upLeft = num;` —
**без** проверки флага.

В нашей реализации это `TerrainTileShema.ResolveMutualSlot` +
`TerrariaTilesetRules.MutualMergeCheckDiagonalIsSelf = true` для земли.
Для взаимной проверки нужна окрестность соседа → окно **5×5**
(`SpriteData`: `SquareSizeByShema = 5`).

## 2. Структура `WorldGen.TileFrame` для камня

```
75556  if (val.X == -1 && val.Y == -1 && (Main.tileMergeDirt[num] || ChecksForMerge[num]))
75558      if (!flag) { flag = true; TileMergeAttemptWeird(num, -1, Main.tileSolid, ...); }
75563–78   нормализация: if (xx > -1 && xx != num) xx = -1;
75580      if (все 4 стороны != -1)      → Блок 1
75960      else                          → Блок 2
76404  }
76551  if (val.X < 0 || val.Y < 0)        → Блок 3 (generic)
76928  if (val.X <= -1 || val.Y <= -1)    → Блок 4 (fallback)
76954  tile.frameX = val.X; tile.frameY = val.Y;
```

Флаги `mergeUp/Down/Left/Right` сбрасываются в начале функции (`73892–73895`) и
выставляются **только** теми ветками, которые назначили кадр.

`v` — вариант текстуры `num27 ∈ {0,1,2}` (`tile.frameNumber()`); в наших тестах
`v = randomTile % 3`.

## 4. Геометрия атласа и связь с `FrameStructure`

- Атлас: `Assets/Resources/TerrariaTiles.png`, 1024×2048.
- Спрайты (bottom-origin в `.meta`): `Tiles_0` → `(234, 915, 287×269)`,
  `Tiles_1` → `(521, 915, 287×269)`.
- Кадр 16×16 px, шаг сетки **18 px** (2 px паддинга) — совпадает с `UvProvider`
  (`GetTileSize() = 16`, `GetPadding() = 2`), который строит сетку 16×16 ячеек.
- Поэтому `FrameStructure(fx, fy) = (frameX / 18, frameY / 18)`:
  например `(162, 0)` → `(9, 0)`, `(144, 180)` → `(8, 10)`.

Проверено попиксельно по дампам: `artifacts/tiles_0_dump.png`, `artifacts/tiles_1_dump.png`.

## 5. Разбор проблемной конфигурации из задачи

`up = Merge, down = Merge, left = Edge, right = Self` — первый блок горизонтальной полосы
камня толщиной 1 внутри земли, выходящей в пустоту слева.

| Шаг | Что происходит | Строка |
|---|---|---|
| 1 | Блок 1 не входит: `left == -1` | 75580 |

| 3 | Ветка `up≠-1 && down≠-1 && left==-1 && right==num` — **входит**, но подветки требуют `up==-2 && down==num` или `down==-2 && up==num`; у нас оба `-2` → кадр **не назначен** | 76041–76081 |
| 4 | Остальные ветки 76082–76402 не подходят | |
| 5 | Generic: подходит **76873** (`up≠num, down≠num, left≠num, right==num`) | 76873 |
| 6 | Результат: `frameX = 162`, `frameY = 18v` → `(162, 0)` для v=0, сетка `(9,0)`; флаги не выставлены | 76878–76889 |

## 6. Особенности и отклонения нашей реализации

### 6.1 Окно 5×5 и перерисовка

`TerrainTileShema` получает окно карты (для земли/камня — 5×5) и классифицирует 8 соседей
центральной клетки. Окно 5×5 нужно потому, что взаимная проверка земли требует
**окрестности соседа** (сосед на расстоянии 1 → его соседи на расстоянии 2).

Следствие для интеграции: при изменении блока кадры могут измениться на расстоянии до 2,
поэтому для террейн-слоя используется `RedrawWorldTile5X` (5×5) вместо `RedrawWorldTile3X`
(`TileDataProvider.ChangeTile` / `SetTile`, `ScreenUpdateManager`). Остальные слои
(вода, свет, фон) остались на 3×3.

### 6.2 Известное отклонение: `TerrainGrass` в `Stone.mergeTypes`

`TileID.Sets.Dirt = {0, 668}` не содержит траву (type 2). Строго по оригиналу камень
рядом с травой получил бы `-1` (Edge) и жёсткую границу. В проекте трава — отдельный
спрайт `Tiles_2` со своей схемой, а на поверхности карты (`TestMapGenerator`/`PreviewGen`)
встречается именно `TerrainGrass`, поэтому для камня трава добавлена в `mergeTypes`.

Это **осознанное отклонение** от оригинала. Если поведение нужно привести строго к 1.4.4.9 —
убрать `TileTypeEnum.TerrainGrass` из `Stone.mergeTypes` и перегенерировать тесты
(ожидания в `BranchTableTests` от этого не изменятся — трава там не участвует).

### 6.3 Что осталось «за кадром»

- Травяное семейство, мши, наклоны/полукирпичи — не портированы (нет таких блоков).
- Ветки для mud/ash/ore (`TileMergeAttemptFrametest`) — не нужны.
- Кеш кадров отсутствует; пересчёт на каждый запрос (~1.55 млн тайлов/с на i7-классе CPU).
