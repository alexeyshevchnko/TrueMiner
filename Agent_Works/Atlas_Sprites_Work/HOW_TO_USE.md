# HOW_TO_USE — инструмент Atlas Outline Transfer

Инструмент редактора Unity для переноса чёрной двухпиксельной обводки блоков
из одного атласа в другой, с точным сохранением расположения пикселей
(никакого масштабирования, смещения или автогенерации обводки).

---

## 1. Где находится инструмент

- Скрипт: `Assets/Editor/AtlasOutlineTransfer.cs` (класс `AtlasOutlineTransferWindow`).
- Это Editor-инструмент: в игру и игровые сцены не подключён, игровые компоненты не затрагивает.
- Резервные копии: `Agent_Works/Atlas_Sprites_Work/backup/`.
- Документация направления: `Agent_Works/Atlas_Sprites_Work/`.

## 2. Как открыть окно

В Unity открыть меню **Tools → Atlas Outline Transfer**.
Появится окно «Outline Transfer».

## 3. Какой атлас назначать в Source Outline Atlas

Атлас, из которого берётся обводка. В текущем проекте это атлас тайлов:

- `Assets/Resources/TerrariaTiles.png` (1024×1024) — в нём блоки уже обведены
  чёрной двухпиксельной обводкой.

Перетащите его в поле **Source Outline Atlas** из окна проекта.
Важно: исходный атлас инструментом НЕ изменяется никогда — из него наоборот только читаются пиксели.

## 4. Какой атлас назначать в Destination Atlas

Атлас, в который обводка переносится. Требования:

- **Обязательное**: размер пиксель в пиксель совпадает с исходным (при несовпадении
  инструмент покажет ошибку и заблокирует перенос — он намеренно не масштабирует и не смещает).
- Ряды/позиции спрайтов внутри атласа должны соответствовать исходному — обводка
  записывается по тем же координатам, где она была найдена.

Перетащите его в поле **Destination Atlas**.

## 5. Настройки обнаружения (по умолчанию — правильные для тестовых атласов)

| Настройка | По умолчанию | Смысл |
|---|---|---|
| Outline Color | Чёрный | Цвет обводки, которую ищем |
| Color Tolerance | 0.12 | Допуск по каждому цветовому каналу (~±30/255), чтобы ловить «почти чёрные» пиксели |
| Outline Thickness | 2 px | Толщина обводки |
| Transparent Alpha < | 0.03 | Пиксели с такой и меньшей альфой считаются прозрачными |
| Exclude Marker Color | ВКЛ | Служебный (маркерный) цвет в исходнике не считается ни обводкой, ни преградой: он исключается из маски, поэтому обводка, «прижатая» к маркерам (например, к розовым рамкам #F777F9 между блоками), не теряется |
| Marker Color | #F777F9 (розовый) | Цвет маркера (пикселем маркера инструмент НЕ управляет — не переносит и не перезаписывает) |

Эти значения проверены на тестовых атласах `outline_src.png` / `outline_result.png`
(920/920 обводочных пикселей, 0 пропусков). Менять их нужно только если обнаружение
на вашем другом атласе даёт отклонения; флажок Exclude Marker Color можно выключить,
если маркеров в атласе нет.

## 6. Как выполнить Analyze

Нажмите кнопку **Analyze**. Инструмент:

1. Считывает пиксели исходного атласа (работает даже если у текстуры выключен Read/Write:
   файл читается с диска во временную текстуру — ассет не трогается).
2. Строит маску непрозрачных пикселей (исключая маркерные, если Exclude Marker Color включён)
   и для каждого пикселя считает глубину от непрозрачного края области.
3. Обводкой считаются **чёрные непрозрачные пиксели не глубже 2 px от края**.
   Чёрные пиксели глубже 2 px — внутренние детали текстур — исключаются
   (их количество показывается в отчёте).
4. Показывает результат анализа:
   - размеры обоих атласов и совпадение размеров;
   - **обнаружено пикселей обводки** (N);
   - **будет перенесено** — сколько из них отличается от целевого атласа (M);
   - **исключено внутренних чёрных пикселей** (глубже толщины);
   - **маркерных пикселей** (исключены из маски, не трогаются);
   - количество связных областей/блоков в исходнике;
   - полная строка использованных настроек (цвет-hex, допуск, толщина, alpha-порог,
     исключение маркера);
   - предупреждения (например, если перенос уже выполнялся — записывать будет нечего).

Анализ без изменения результата можно запускать сколько угодно раз.

## 7. Как проверить предварительный результат

Нажмите кнопку **Preview** — появятся вкладки трёх режимов:

| Вкладка | Что показывает | Зачем |
|---|---|---|
| **Наложение на цель** | Целевой атлас поверх с наложенной обводкой | Как выглядит итог |
| **Обнаруженная маска** | Ровно те пиксели, что будут перенесены (на прозрачном фоне) | Сразу видно, не потерялись ли участки обводки (разрывы здесь = пропуски обнаружения) |
| **Обводка исходника** | Чёрные пиксели исходного атласа в его координатах | Эталон для сравнения с маской |

Это временные текстуры внутри окна: **ассеты в этот момент не изменяются**.
Сравните «Обводку исходника» и «Обнаруженную маску»: если маска где-то беднее
эталона — увеличьте Outline Thickness или добавьте нужный маркер в Marker Color
(но по умолчанию настройки подходят к тестовым атласам без изменений).
Кнопка «Clear Preview» убирает превью.

## 8. Как выполнить Transfer Outline

Нажмите кнопку **Transfer Outline**. Инструмент:

1. Обязательным первым шагом создаёт резервную копию файла целевого атласа
   (см. раздел 9). Если копию создать не удалось — перенос отменяется.
2. Записывает только обнаруженные пиксели обводки в целевой атлас по исходным координатам,
   заменяя там, где цвет реально отличается (уже совпадающие пиксели не перезаписываются —
   повторный запуск переносит только недостающую обводку).
3. Сохраняет и реимпортирует результат:
   - целевой атлас в формате PNG обновляется **in-place** (все пиксели вне обводки
     сохраняются без изменений; настройки импорта и `.meta` не трогаются);
   - если целевой файл в формате, который нельзя безопасно перезаписать PNG-данными
     (например TGA/JPG с особыми настройками), результат сохраняется рядом отдельным
     ассетом `ИмяАтласа_outlined.png`, а инструмент явно предупредит об этом.
4. В окне и в Console появится отчёт: сколько пикселей записано, путь результата и путь копии.

## 9. Где находится сохранённый результат

- Для PNG-целевого атласа результат — тот же файл атласа
  (например `Assets/Resources/TerrariaTiles.png`), обновлённый через реимпорт в Unity.
- Для целевого файла в отображаемом отдельно формате результата: рядом с ним
  `ИмяАтласа_outlined.png` (путь показан в окне и в Console).
- Служебные копии и превью-иллюстрации: `Agent_Works/Atlas_Sprites_Work/preview/`.

## 10. Как восстановить исходный целевой атлас из резервной копии

Резервная копия создаётся до записи в папке:

```
Agent_Works/Atlas_Sprites_Work/backup/<имя_файла>_<дата-время>.backup.<расширение>
```

Чтобы откатить:

1. Откройте в проводнике папку backup (в окне инструмента есть кнопка «Открыть папку backup»).
2. Закройте или снимите фокус с Unity на время копирования (не обязательно, но безопасно).
3. Скопируйте нужный `.backup`-файл поверх текущего файла атласа в `Assets/...`
   (например `TerrariaTiles.png`) с исходным именем.
4. Верните фокус в Unity — оно само выполнит reimport (или ПКМ по файлу → Reimport).
5. У дочерних `.meta` ничего менять не нужно — восстанавливается только содержимое файла текстуры.

Удалять резервные копии не рекомендуется: они позволяют всегда вернуться к исходному
состоянию (организация «отката без риска»).

## 11. Частые ошибки и что они значат

| Сообщение | Что делать |
|---|---|
| «Назначьте оба атласа…» | Перетащите в окне оба атласа (Source и Destination). |
| «Размеры атласов не совпадают…» | Найдите/сделайте целевой атлас того же размера — инструмент сознательно не масштабирует и не подгоняет. |
| «…недоступна для GetPixels… включите Read/Write» или «формат файла… нельзя безопасно прочитать» | Либо включите Read/Write Enabled в Import Settings текстуры, либо работайте с PNG-файлом. При «Read/Write»-ошибке файл на диске не пострадает. |
| «Обводка не обнаружена…» | Перенос заблокирован: проверьте, что обводка в исходном атласе есть, и настройки цвета/допуска/толщины. |
| «Файл … уже существует» (для `*_outlined.png`) | Удалите или переименуйте старый файл результата. |
| «Все обнаруженные пиксели уже совпадают…» | Перенос уже выполнялся: повторный запуск безопасен, он ничего не изменит. |

## 12. Безопасность данных (кратко)

- Исходный атлас не изменяется никогда.
- Целевой атлас изменяется только после успешной резервной копии.
- Пиксели вне обнаруженной обводки в целевом атласе сохраняются байт в байт.
- `.meta` целевого атласа не изменяются (изменяется только содержимое текстуры).
- Окно никогда не запускает перенос само: только по нажатию кнопки.

## 13. Алгоритм обнаружения в одну строку

«Обводка» = непрозрачный пиксель атласа, цвет которого в пределах допуска совпадает
с заданным цветом (чёрный), и который лежит **не глубже 2 px от непрозрачного края**
своей связной области, при условии, что маркерный (служебный) цвет исключён из маски.

Проверено на реальных тестовых атласах `outline_transfer` (288×270):
обнаружено 920/920 пикселей обводки, перенос в вычищенный `outline_result.png`
дописал ровно 94 недостающих пикселя, после чего результат по обводке совпал
с исходником пиксель в пиксель (0 несоответствий), розовые маркеры не тронуты,
повторный перенос записал 0 пикселей.

## 14. История исправления точности (сессия 14)

Прежние настройки по умолчанию давали «обрывистую» обводку на тестовых атласах:
94 из 920 пикселей пропадали. Причина (установлена по пиксельным данным, не наугад):
перед обводкой между блоками стоят НЕПРОЗРАЧНЫЕ маркерные пиксели розового
цвета #F777F9, и прежний алгоритм «глубина от прозрачного края ≤ 2» считал находящуюся
за ними обводку «слишком глубокой».

Исправлено: маркерный цвет исключается из маски-барьера (флажок `Exclude Marker Color`,
цвет `Marker Color`). Розовые пиксели инструмент не трогает; обводка, прижатая к ним,
переносится полностью. Никакого «склеивания разрывов» морфологией нет и не добавлялось —
форма обводки берётся строго из исходника.
