# REMAINING_ISSUES — Непроверенные сценарии и оставшиеся вопросы (миграция Input System)

## 1. Требуют ручной проверки (невозможно без человека/устройства)
| # | Сценарий | Почему не проверено | Как проверить |
|---|---|---|---|
| 1.1 | Живое клавиатурное/мышиное управление в Play Mode (движение, прыжок, копание, атака, хотбар, сумка) | автозонд не эмулирует ввод; замены 1:1 и компилируются, но «ощущение» ввода не измерялось | Открыть проект, Play, пройтись/прыгнуть/копнуть/открыть сумку (B или Tab), переключить хотбар 1–9 |
| 1.2 | Два джойстика одновременно двумя пальцами (перемещение + прицел), проверка залипания | нет сенсорного устройства; архитектура не менялась — UltimateJoystick/JoystickTouchArea работает через EventSystem в режиме MultiTouchAndTrack | На Android-сборке или Device Simulator: одновременно вести оба джойстика, отпустить поочерёдно |
| 1.3 | Сборка под Android / iOS | вне прогона | Сделать Build; при проблемах: Input System поддерживает Android по умолчанию |
| 1.4 | Касания UI поверх джойстиков (баг/иконки) | то же зондом нельзя | Play: тапнуть по кнопкам UI — касание не должно активировать джойстик и наоборот |
| 1.5 | Раскладка клавиатуры (KEY-события Input System не зависят от раскладки для прямой привязки клавиш) | не требовалось | — |

## 2. Осознанные решения (не требуют действий)
- Демо-скрипты CartoonFx (`CFX2_Demo`, `CFX3_Demo`) переведены на новый API, чтобы не оставлять мёртвый старый API в коде; сами демо-сцены игрой не запускаются.
- `MainSceneLight.unity` не содержит StandaloneInputModule — не тронута (сцена вне игрового цикла; при необходимости подключить InputSystemUIInputModule вручную при её использовании).
- Пакет установлен как зависимость без Samples; PlayerInput/Input Actions-ассеты не создавались — «не создавай избыточную архитектуру».
- Пользовательские незакоммиченные файлы (`PackageManagerSettings.asset`, `ProjectVersion.txt`, `ProjectSettings/PhysicsCoreProjectSettings2D.asset`, `ProjectSettings/ProjectAuditorSettings.asset`) сознательно не включены в коммит миграции — они относятся к обновлению Unity 6000.6, а не к Input System.

## 3. Риски
- **InputSystemUIInputModule без назначенных действий**: действия создаются автоматически в Awake; если в будущем понадобится кастомизация (например, поведение точек касания), задать `Actions Asset` вручную через Inspector — сейчас ноль конфигурации = ноль расхождений со старым поведением по умолчанию.
- При следующем обновлении пакета (1.20.x → новее) повторить smoke-тесты Play Mode (как в этой задаче).
